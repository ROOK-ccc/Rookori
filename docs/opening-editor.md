# オープニング教材の編集と公開

## PCで教材を編集する

1. リポジトリのフォルダーで `node opening-editor-server.cjs` を実行し、ブラウザーで `http://127.0.0.1:8000/opening-editor.html` を開きます。終了するときはターミナルで Ctrl+C を押します。
2. 日本語名、英語名、別名、教材IDで検索し、オープニングとバリエーションを選びます。着手の解説欄に移動すると、その手を指した後の盤面が表示されます。右側で教材の文章、編集前後の差分、必須欄の入力状況を確認できます。
3. 作業途中は「下書きを保存」を押します。下書きは同じブラウザーとローカルURLで開き直せます。別の教材を編集した後も、保存した下書きは教材ごとに残ります。
4. 確認した教材で「この教材を公開候補に書き出す」を押します。ダウンロードした `opening-edits-data.js` を作業フォルダーの同名ファイルに反映し、GitHub Desktopで差分を確認します。複数教材を公開する場合は、1件を反映するたびにエディターを再読み込みしてから次の教材を書き出すと、直前の変更も含まれます。別の作業で同ファイルに変更が入っていれば差分を統合してください。
5. 学習画面と生成されたHTMLで確認し、確認済みの変更を通常のGitワークフローに載せます。教材ID、バリエーションID、手順、学習記録は編集対象外です。手順の追加が必要な場合は教材の元データを編集し、既存の合法手テストを実行してください。

### 編集項目

日本語名、英語名、別名、概要、レベル、前提知識、基本の狙い、白番・黒番の狙い、駒の配置、長所・短所、ミス、実戦の要点、各手の解説、よくある疑問、出典を編集できます。任意でSEOタイトルと説明を設定できます。空欄なら教材名と概要から生成します。更新日は内容を変更した実際の日付を入力してください。空欄の教材にはサイトマップの `lastmod` を付けません。

既存教材は公開扱いです。編集中の内容は書き出しとファイル反映を済ませるまで公開されません。新規の読み物は `learning-articles.cjs` に追加し、本文とリンクを確認してから `status: 'public'` にします。公開ビルドのファイル一覧に編集ツールや読み物の元ファイルは入りません。

## 公開用HTMLの確認

- `node publish.cjs --target cloudflare-preview` で確認用ビルドを生成します。計測は無効で、インデックス登録の対象外を示す `noindex` が付きます。
- `node publish.cjs --target cloudflare-live` は正式用ビルドです。両者の出力先は `.rookori-cloudflare-assets/` です。Wranglerでローカル配信中の場合は、停止してから次のビルドを生成してください。
- `node publish.cjs --target pages` は旧サイト向けです。旧サイトの教材タブから正式サイトの教材へ移動できます。一括バックアップと移転案内は旧サイトで引き続き使えます。
- 新サイトでは `/openings/` と `/guides/` から教材を探せます。教材ごとの正規URLを `/sitemap.xml` に載せます。検索からの着地を含め、公開後はSearch Consoleで対象URLを検査してください。
- 検索用の静的HTMLはオンラインで配信します。盤を使う学習画面は、従来どおりPWAのオフラインキャッシュで読めます。

## 計測と集計

サイト上で計測に同意した後の操作が対象です。GA4のウェブデータストリームで拡張計測機能をオフにし、履歴変更の自動ページビューとフォームや検索等の自動収集を無効にしてください。Rookoriが固定した画面とイベントを送る構成です。診断回答、棋譜、メモ等をイベントのパラメータには含めません。

| イベント | 送信する操作 |
| --- | --- |
| `chess_type_start`・`chess_type_complete` | 16タイプ診断画面へ入ったとき・最後の回答から結果へ進んだとき |
| `opening_quiz_complete` | オープニング診断の最後の回答から結果へ進んだとき |
| `opening_view` | 学習画面で定跡を開いたとき・個別の静的定跡ページを表示したとき |
| `opening_practice_start`・`opening_practice_complete` | 定跡の通常練習を開始したとき・最後の手順まで進んだとき |
| `review_complete` | 復習対象として出された定跡の手順を完了したとき |
| `dashboard_view` | 学習ダッシュボードを表示したとき |
| `share` | 診断のリンクコピー、リンク共有、画像共有のいずれかが成功したとき |

GA4の「探索」で、集計期間を指定し、イベント名を `opening_practice_complete` または `review_complete` に絞り、指標に「アクティブ ユーザー」を選ぶと、同意済みの完了者を集計できます。教材を読み終えたことや診断結果の表示はこの定義に含めません。再訪学習者は「セッションをまたぐ」ユーザーシーケンスで、定跡閲覧・練習開始・練習完了・復習完了のいずれかが別セッションで2回以上起きた利用者を集計します。

SNSのリンク例は `?utm_source=instagram&utm_medium=social&utm_campaign=opening_learning` です。同一サイト内の教材・学習画面への遷移でUTMを保持します。計測へ送る値は `analytics.js` の許可リストから選ばれ、任意入力値やその他のクエリは除外します。新しいキャンペーン名を運用で使う場合は先に許可リストを更新してください。公開後はネットワークログとGA4のリアルタイム画面を並べて、同意前後と重複の有無を確認できます。
