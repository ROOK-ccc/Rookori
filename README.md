# Rookori（ルーコリ） v4.4.7

Rookoriは、チェスを学び始めた一人の初心者が、自身の経験をもとに開発している日本語チェス学習サイトです。チェス未経験の人から、実戦で使える戦法を増やしたい人まで、自分のペースで学べます。

Rookoriの正式公開先は独自ドメインです。 [Rookoriの公開サイト](https://rookrori.com/)

旧サイトの学習記録と対局履歴は、一括バックアップをダウンロードし、新サイトで「既存データを残して追加する」を選ぶと移せます。ブラウザーの保存データはドメインをまたいで自動では引き継がれません。 [旧サイトのバックアップ](https://rook-ccc.github.io/Rookori/#backup) · [新サイトの復元](https://rookrori.com/#backup)

- **チェスをまだ知らない人へ**では、ルール・駒の練習・理解度チェックを始められます。
- **チェスを少し知っている人へ**では、2つの診断やオープニング学習を試せます。
- **もっと強くなりたい人へ**では、問題演習・復習・棋譜の振り返りに進めます。

「Rookoriについて」では、初心者が気後れせずにチェスを始められる場所を目指し、2つの理念と4つの柱を紹介しています。

- **チェス16タイプ診断**では、初心者向けと経験者向けの各12問からプレイスタイルを探ります。
- **オープニング診断**では、8問から白番・黒番の対1.e4・黒番の対1.d4で学ぶ戦法を1つずつ提案します。1.e4と1.d4は、相手がキング前またはクイーン前のポーンを初手で2マス進めることです。診断結果から、手順をチェス盤で学べます。

教材や対局復習で点線の下線が付いた用語は、マウスを重ねるかクリック・タップすると意味を確認できます。キーボードでは用語にフォーカスし、下矢印キーで「用語集で詳しく見る」に移動できます。Escキーや外側のクリック・タップで閉じられます。

「チェス用語集」には基本ルール・戦術・戦略・オープニング・対局分析の40語があります。日本語、英語、別表記で検索し、分野で絞り込めます。

## コンピューター対戦

ホーム・対局メニュー・入門コースから「コンピューター対戦」を開けます。練習モードでは、ヒントや「待った」を使って一手ずつ試せます。時間付き対局では、一時停止や、時間切れ後に同じ局面から時間無制限で続けることもできます。実戦モードは補助機能を使わずに指します。対局設定は次回に引き継がれます。

CPUはポーンからキングまでの6段階です。持ち時間は無制限、プリセット、自由設定から選べます。「3＋2」は一人3分で、着手ごとに2秒を加算します。

着手のある終了対局は、練習・実戦とも既存の対局履歴に自動保存されます。「この対局を復習する」から盤面をすぐ再生でき、PGNはコピー・ダウンロードも可能です。時間切れ後の継続練習は元の勝敗と別に記録します。v3.2.1の簡易記録は、対局設定の「v3.2.1までの実戦結果」から確認できます。

途中の対局は同じブラウザーに1局保存し、設定画面から再開できます。ページを離れている間は時計が止まり、別タブへ切り替えただけの場合は進みます。再開した実戦は履歴で区別します。対局履歴のバックアップには終了済みの棋譜とメモが含まれます。

エンジンはStockfish 19 LiteのシングルスレッドWASM版（stockfish.js v19.0.0）です。対局開始時にGitHub Pagesの同一パスからWeb Workerを読み込みます。ルールと対局状態はchess.js側で管理し、エンジンとはUCIのテキストでやり取りします。対戦・ヒント・今後の解析では別の探索設定を使います。PCで試す場合は、リポジトリで `python -m http.server 8000` を実行して `http://localhost:8000/#cpu` を開きます。 [Stockfishの配布元・GPLv3・対応ソース](vendor/stockfish/NOTICE.txt) · [chess.jsのBSD 2-Clauseライセンス](vendor/chess.LICENSE.txt)

三回同一局面と50手ルールは、条件が成立した後、自分の手番で請求できます。5回・75手は自動です。時間切れ時は、相手がキングだけの場合やchess.jsが駒不足と判断する場合を引き分けにします。着手予定の手による事前請求と、駒の配置に依存する特殊なチェックメイト不能局面の完全な判定は対象外です。 [FIDEチェス規則 6.9・9.2〜9.6](https://handbook.fide.com/chapter/E012023)

相手から取った駒はアイコンで表示できます。駒得の数値は、盤に残るポーン1点、ナイト・ビショップ3点、ルーク5点、クイーン9点の合計の差です。キングは数えません。2つの表示設定はモードごとに保存し、実戦では駒得の数値を初期状態で非表示にします。

## Lichessの公開棋譜を取り込む

対局履歴や「対局を振り返る」から「棋譜をまとめて取り込む」を開きます。LichessやChess.comでご自身が書き出したPGNファイルや棋譜の文章を選び、候補の中から使用色と保存対象を確認できます。書き出しの手順は取り込み画面から確認できます。

ブラウザーからLichess APIへの直接取得は休止中です。公式仕様が求める、アプリを識別できる `User-Agent` を確実に送れる方法、またはブラウザー直結への例外がLichessから確認できた場合に、公開設定の変更を検討します。CORSで応答が読めることはヘッダー要件の確認とは別です。代わりに、Lichessで保存した終了済みの棋譜を「対局を振り返る」から手動で取り込めます。過去にこのブラウザーに保存したユーザー名は「外部サイトとの連携」から削除できます。既存の取り込み済み棋譜は対局履歴に残ります。 [Lichess API仕様](https://lichess-org.github.io/api/#description/user-agent-header) · [Lichess API利用のヒント](https://lichess.org/page/api-tips)

直接取得用の実装では、Web Locksに対応する同一オリジン内で取得を直列化し、読み取れたHTTP 429の後は1分または `Retry-After` の長い方を待ちます。Lichessに送信するのは取得時のユーザー名と条件で、プロフィールの追加取得は行いません。運営者向けの確認事項として、CORSで429が読み取れない場合の扱いも再開前に確認してください。

## 対局を振り返る

ホーム・今日の学習・メニューの「対局を振り返る」から始めます。最近の対局や対局履歴を開いたり、手元の棋譜を選んだりできます。「棋譜をまとめて取り込む」では複数対局を選択して保存できます。「棋譜を直接入力する」では、保存前に盤面を再生できます。棋譜（対局で指した手の記録）が手元になければ「サンプル対局で試す」を開いてください。

- 盤の下のボタンで進む・戻る・最初・最後に移動できます。「指した手」で手を選ぶと、その直後の盤面を表示します。PCでは左右の矢印キーも使えます。文字の入力欄とチェス盤にフォーカスしているときは、各欄のキーボード操作が優先されます。
- 通常の初期配置から始まる棋譜では、序盤の盤面を教材に対応する36の局面と照合します。手順が前後しても駒の配置・手番・キャスリング権・有効なアンパッサンが一致すれば候補になります。「分類の詳細」には、一致した局面のECOコードが表示されます。対応する局面がなければ判定を省き、再生は引き続き使えます。 [Lichessの分類データ（CC0 1.0）](https://github.com/lichess-org/chess-openings)
- 「気になった局面を保存する」では、局面だけ、またはメモを添えて保存できます。各対局で同じ局面番号に1件まで保存でき、一覧から再表示・編集・削除できます。最後に迷ったところを見返したり、「次の学習」から関連する教材に進んだりできます。
- 「対局を履歴に保存」または局面の保存で「対局履歴」に追加されます。履歴は対局名・対局者・メモで検索できます。保存済みの対局は元の棋譜として書き出せます。棋譜中のコメントや別の手順は書き出しに含まれ、盤には実際に指した本譜を再現します。終了記号のない棋譜は記録されている範囲を表示します。特殊なルールで行うチェスには対応していません。
- 対局とメモは、現在のブラウザーの IndexedDB に保存します。今までの学習記録は従来どおり localStorage に保存されます。「対局履歴」のバックアップから対局とメモをまとめて JSON に書き出せます。復元ではファイルを検証した後、確認を経て現在の対局履歴を置き換えます。取り込み元が同じ棋譜は履歴で重複保存されません。

## 今日の学習・復習・上達記録

- 初めての利用や診断だけの利用では紹介型ホームを表示します。入門レッスンの完了やオープニング学習・暗記の記録があると、ホームは学習ダッシュボードになります。ホーム下部のボタンで手動指定や自動選択に戻せます。
- 「今日の復習」では、期限が来た手の直前まで盤面を再現します。ヒントなしの初回正解で翌日、3日後、7日後、14日後、30日後と間隔を延ばします。誤答やヒントがある場合は翌日に戻し、習熟度を下げます。日付はブラウザーの現地日付を使い、解決した手は同じ日に再出題しません。
- 「今日の学習計画」は期限のある復習、入門の続きまたはオープニングの学習、最大10問の練習です。練習問題は過去に間違えた問題、未解答、前回の正解から7日以上経った問題、その他の順に選びます。同じ日に同じ問題を解き直しても完了数は1件です。
- 戦法一覧では日本語名と英語名で検索し、色と難易度で絞り込めます。難易度は既存データの複雑さを目安に、バリエーションは経験者向けとして表示します。
- メニューの「学習データのバックアップ」で、入門進捗、暗記履歴、復習予定と日別計画をJSONで保存できます。復元前に形式の確認と置き換えの確認を行います。自作問題はエディターのJSON出力から保存してください。

### 上達記録の読み方

「上達記録」では、今週と過去7週間の学習カレンダー、暗記・復習の初回正解率、日別学習量、戦法別の習熟度を確認できます。グラフの下の日付欄はキーボードで操作できます。学習日と週の区切りは現在の端末の現地日付を使い、週は月曜始まりです。

初回正解率には、同じ日の同じ手について、練習をやり直したりヒントを使ったりした場合も、最初の回答だけを数えます。Ver.2.4以前の履歴は、保存済みの回答集計を使います。当時の記録で最後まで解けなかった手の回答や種類が記録されていない学習の内訳は、わかる範囲だけ表示します。

習熟度は登録手順のうち練習した手の割合と、手ごとの復習段階を中心に算出し、初回の回答、ヒント、期限超過も反映します。同じ日に同じ手を繰り返しても復習段階は上がりません。数値は教材に対する習得の目安です。

既存の `chesspath.intro.v1` と `chesspath.opening-history.v1` は引き継ぎ、復習と計画を `chesspath.learning.v1` に保存します。旧履歴で指したと分かる手は翌日を初回期限として登録し、手ごとのヒントの内訳は旧履歴に含まれていないため引き継ぎません。

右上の☰を押すとメニューが開きます。項目を選ぶか、背景を押すか、Escキーで閉じられます。

## Windowsで開く

1. エクスプローラーで `ChessPath` フォルダーを開きます。
2. `index.html` をダブルクリックします。拡張子を表示していない場合は `index` と表示されます。
3. EdgeやChromeでサイトが開いたら、「学習を始める」か、受けたい診断を選びます。事前のインストールや起動コマンドは不要です。

ファイル名と配置はそのままにしてください。編集後はブラウザーで `Ctrl + R` を押すと変更を反映できます。

## はじめてのチェス

トップで「チェスを始める」→「最初のレッスンを始める」を押します。盤の見方から始まる全6章・26レッスンで、基本ルール、6種類の駒、特別なルール、チェックと引き分け、序盤の考え方、理解度チェックを学べます。

駒を選ぶと合法な移動先に印が付きます。課題に合う手を指すか正しい選択肢を選ぶと解説が表示され、次のレッスンへ進めます。ヒントを見たり、同じ課題を最初からやり直したりできます。理解度チェックは7問で、結果には初回で正解した数と再挑戦を含めて解けた数が表示されます。

完了したレッスン、最後に開いた章・レッスン、理解度チェックの結果を、現在のブラウザーの `localStorage` に保存します。別の端末には同期されません。入門コース一覧の「保存した進捗を削除する」から記録を消せます。保存が使えない環境では、同じタブを開いている間に学習を続けられます。

教材を編集するときは `intro-data.js` を開きます。駒を動かす課題では、FENという文字列で盤面と手番、UCIという表記で正解手を指定できます。たとえば `e2e4` は「e2からe4へ動かす」です。ルールの参照資料はFIDEのチェス規則です。 [FIDE Laws of Chess](https://handbook.fide.com/chapter/E012023)

## 問題作成エディター

エクスプローラーで `editor.html` を直接開きます。「保存済みの問題・JSONを管理」を開くと、保存済みの問題や既存教材の編集、JSONの読み込みができます。

1. 駒を選んで置きたいマスを押します。「移動」は駒→移動先、「削除」は消すマスを押します。FENがある場合は「FENから読み込む」で手番、キャスリング権、アンパッサン、手数も読み込めます。
2. タイトル、章、難易度、問題文、ヒント、正解・不正解解説を入力します。問題IDは自動で作られ、タイトルを編集しても変わりません。「教材を編集」では既存の駒を動かす課題を同じID・同じ章のまま編集できます。「作業中の問題を複製」では新しいIDを作ります。
3. 「盤で新しい正解を指す」を押し、盤上で指して「この手順を登録」を押します。単手問題は1手ずつ、複数手では自分・相手・自分の順で最後の自分の手まで登録します。正解が複数あれば繰り返します。同じ手まで進んだときの相手の応手は1つにそろえてください。各手順は登録後に編集・削除できます。
4. 「プレビュー」で学習者と同じ判定を試し、「問題を保存」を押します。「最後がチェックメイトか確認」を選ぶと、各手順の最後がチェックメイトか検証します。そのほかの問題文と正解の対応はプレビューで確認してください。
5. 下書きや保存した問題は今使っているブラウザー内に保存されます。「この問題のJSON」または「保存済みの一括JSON」でバックアップできます。JSONは `schemaVersion: 1` を持ち、「JSONを読み込む」から編集に戻れます。

「指定の駒だけで練習」は開始マスを指定する1手の課題です。合法手はchess.jsを使い、キングとナイトだけのような駒不足の盤でも駒の動きを練習できます。

### 作った問題を教材へ反映する

1. エディターで反映する問題を保存し、「公開教材ファイルを書き出す」を押します。
2. ダウンロードした `course-problems.js` をChessPathフォルダーにある同名ファイルと入れ替えます。
3. `index.html` を開き直して「はじめてのチェス」を開きます。新しい問題は選んだ章の末尾に表示されます。既存IDを編集した問題は元の位置に表示され、それまでの進捗を同じIDで参照します。

エディターに「編集中」「下書き保存済み」と、現在の保存済み問題について「公開用ファイル未出力」または「公開用ファイル出力済み」が表示されます。出力後は置き換え手順が表示されます。出力済み表示はその版の書き出しを実行した記録で、サイト側のファイルが置き換わったことまでは確認しません。

公開用のフォルダーを作る場合は、Node.jsで `node publish.cjs` を実行します。保存済みのJSONを直接使う場合は `node publish.cjs "rookori-problems.json"` のようにファイルを指定します。公開するのは作成された `chesspath-public-…` フォルダーの中身だけです。エディターと下書きはこのフォルダーに含まれません。

## オープニング診断

`opening-scoring.js` に各回答で重視する特徴を登録しています。攻めやすさや覚える量などの希望値を1〜5で表し、候補の評価値との差が小さいほど優先します。質問内に特徴が複数ある場合は、その差の平均を使います。

経験を聞くQ1と覚えたい手順の量を聞くQ4は重みを大きくしています。どちらかでAを選ぶと、複雑さと学習負担がともに3以下の候補に絞ります。両方がB以上なら4まで、両方がCなら5まで候補に入ります。同点の場合は学習負担が小さい順、次に複雑さが小さい順、さらに同じ場合はIDの辞書順で選びます。表示する理由は、候補の特徴に最も近い回答に基づきます。

評価はRookori独自の学習用の目安です。戦法の成立には相手の応手が関わり、3枠はよくある初手を学ぶための基本セットです。`opening-data.js` の `moves` には、初期配置からの代表的な手順をUCI形式で登録しています。たとえば `e2e4` は「e2からe4へ動かす」の意味です。戦法の分類と手順は [Lichessのオープニング分類データ](https://github.com/lichess-org/chess-openings) を参考にしています。

## チェス盤で学ぶ

1. オープニング診断の結果カードで「盤上で学ぶ」を押すか、戦法一覧から学びたい戦法を選びます。
2. 「次の一手」を押すと白と黒が交互に進み、直前の移動元と移動先が金色になります。解説には、指した手の狙いが表示されます。
3. 自分で指したいときは、手番の駒を選び、印のついた移動先を押します。キーボードでは盤にTabキーで移動し、矢印キーとEnterキーで操作できます。
4. 基本手順と違う手を指したあとは自由に試せます。違う手を「一手戻る」で取り消すと、基本手順の続きに戻れます。「最初からやり直す」は初期配置に戻します。
5. 黒番の戦法は「黒を手前にする」で盤を回転できます。画面上のリンクから、入ってきた診断結果や戦法一覧、または学習トップに戻れます。
6. 最後の一手まで進むと、最初から学び直す、ほかの戦法を見る、学習トップに戻る、のいずれかを選べます。

同じタブでブラウザーの「戻る」「進む」を使うと、その履歴にある診断の回答やオープニング学習盤の局面が復元されます。戦法のURLを別のタブで直接開くと初期配置から始まります。

駒は押したまま移動先へドラッグするか、駒と移動先を順にクリック・タップします。ドラッグ中に盤の外へ離したり、Escを押したりすると、駒は元の位置に戻ります。タッチ画面でページをスクロールするときは、駒以外の場所から指を動かせます。

### 暗記と復習

1. 戦法の解説画面で「暗記モードで練習」を押します。白番・黒番を選べます。
2. 自分の手を指すと、相手の応手が少し待ってから再生されます。登録手順と違う手を指したときは同じ局面で再挑戦できます。必要なら「考え方」「駒の種類」「正解手」の順でヒントを見られます。
3. 最後まで指すと結果が表示されます。ヒントなしの初回正解率は、再現した自分の手のうち、ヒントを見る前に最初の試行で正解した手の割合です。
4. メニューの「復習する」で、前回の不正解・ヒントが多い戦法を優先して確認できます。同じ件数なら最後の練習日が古いものを先に表示します。

履歴は現在のブラウザーの `chesspath.opening-history.v1` に保存します。戦法・バリエーション・手順・色、日時、途中または完了の状態、誤答手、ヒント回数を記録します。初心者教材の進捗は別に保存します。暗記画面を開き直すと局面は最初から始まります。

### シシリアン・ディフェンス

戦法一覧で「シシリアン・ディフェンス」を開き、「8バリエーションを比べる」を選びます。黒の主な駒組みはナイドルフ、ドラゴン、クラシカル、アクセラレーテッド・ドラゴン、スヴェシニコフ、シェベニンゲンです。白が選ぶ対抗策はアラピンとクローズド・シシリアンです。すべて代表手順を解説・暗記の両方で確認できます。 [Lichessのオープニング分類](https://lichess.org/opening/tree)

昇格するときは4種類から駒を選べます。チェックメイトやステイルメイトなどで対局が終了すると、盤に理由が表示されます。この学習盤では、同じ局面が3回現れた場合や50手ルールに達した場合も引き分けとして表示します。

手順や日本語解説を直すときは、`opening-data.js` で戦法のIDを探し、`['e2e4', 'キング前のポーンを中央に進めます。']` のような行を編集します。手と解説は同じ行に記録されています。

## 動作確認

- 12問すべてでAを選ぶと `ATCI`（炎の戦術家）、すべてでBを選ぶと `SPLD`（盤上の建築家）になります。

- オープニング診断はトップページの専用ボタンから始めます。8問を進め、途中で回答を変更してください。結果で白番・対1.e4・対1.d4のカードを確認し、「もう一度診断する」で回答が初期化されることを確認してください。
- Node.js が入っている場合は、ターミナルでこのフォルダーを開き、`node --test` で両診断の採点、学習盤の進行、URLと履歴の処理を確認できます。

画面幅320・375・430・768・1024・1440pxで、ホーム、入門、診断、戦法の学習・暗記、対局復習を開きます。盤面や診断結果に横スクロールが出ないこと、操作ボタンが画面内に収まることを確認します。

### 初めて使う人との操作確認

保存された学習記録がないブラウザーで、次の課題を一つずつ伝えます。ボタンの場所を先に示さず、最初に選んだ入口と、止まった画面で探していたものを聞き取ります。

1. 最初のレッスンを始め、対局の最初に指す色を答える。
2. 対局の序盤で自分に合う戦法を探す診断を開き、結果まで進める。
3. 診断結果から一つの戦法を盤で学び、一手進めて診断結果へ戻る。
4. サンプル対局を一手進める。その後、短い棋譜を貼り付けて同じ操作を行い、盤の変化を見る。
5. 点線の付いた用語の意味を開き、閉じて元の操作を続ける。

## SNS共有カード

診断結果の4軸の下に共有カードが表示されます。タイプ名・タイプコード・キャッチコピー・4軸の文字と特徴を1枚にまとめています。「PNG画像を保存」で、1200×1500px（縦4:5）の `Rookori-ATCI.png` などを保存できます。画像ファイルの共有に対応した環境では「画像を共有」も表示されます。

## GitHub Pagesを更新する

### 初回の設定

GitHubのRookoriリポジトリで **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に切り替えます。自動公開の設定は `.github/workflows/deploy.yml` に入っています。 [Rookoriリポジトリ](https://github.com/ROOK-ccc/Rookori) · [GitHub Pagesの公開元設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

Windowsでは、GitHub Desktopの **File → Clone repository** から既存リポジトリを開発フォルダーとは別の場所にコピーします。初回は、開発フォルダー直下のソース、最新の `course-problems.js`、テスト、`publish.cjs`、`README.md` と、`brand`、`pieces`、`vendor`、`.github` をクローン先の同じ階層へコピーします。GitHub側で自作問題を更新した場合は、`course-problems.js` の差分を確認し、新しい内容を取り込んでから送信します。ZIPや過去バージョンのフォルダーはコピーの対象外です。エディターをGitHubに置く場合はリポジトリから閲覧できるため、ローカル専用にしたい場合は `editor.html`、`editor.css`、`editor.js` を開発フォルダーに置いておきます。 [GitHub Desktopでクローンする方法](https://docs.github.com/en/desktop/adding-and-cloning-repositories/cloning-and-forking-repositories-from-github-desktop)

### 毎回の更新

GitHub Desktopで `main` の **Changes** を確認し、**Commit to main → Push origin** の順に押します。GitHubの **Actions → Deploy Rookori to GitHub Pages** で実行結果を確認できます。テストか公開用ファイルの生成が失敗したときは、赤いステップを開くと原因を確認できます。成功すると `/Rookori/` のURLに反映されます。 [GitHub Desktopでコミットと送信をする方法](https://docs.github.com/en/desktop/making-changes-in-a-branch/committing-and-reviewing-changes-to-your-project-in-github-desktop?platform=windows)

手元で公開用ファイルだけを確認する場合は、これまでどおり `node publish.cjs` を使えます。Actionsでは `node publish.cjs --print-output` が返したフォルダーだけを公開します。

## 診断結果のリンク

診断結果で「結果のリンクをコピー」を押します。自動コピーが使えない場合は、表示されたURLを長押しするか、PCなら選択した状態で `Ctrl + C` を押してコピーできます。対応端末では「結果のリンクを共有」からも送れます。

リンクを開くと、12問に答えなくても同じ結果を表示できます。「自分も診断する」からモード選択に進めます。リンクに含まれるのはタイプと診断モードで、回答の内容は含まれません。

`index.html` を直接開いて作ったリンクは自分のPC内のファイルを指します。他の端末との共有には、両方の端末が開けるサイトのアドレスを使ってください。静的ホスティングには `node publish.cjs` で作成した公開用フォルダーを使います。

## Google 検索とアクセス解析

正式サイトのcanonical、OGP、`robots.txt`、`sitemap.xml` は `site-config.cloudflare.json` の `siteUrl` を使います。旧サイトは `site-config.json` の `migrationUrl` で正式サイトをcanonicalに指定します。サイトマップには各サイトのトップページを載せます。

### Google Search Console

正式サイトは `rookrori.com` のドメインプロパティで管理します。以下は旧GitHub Pagesの確認手順です。

1. Search Console の **プロパティを追加 → URL プレフィックス** で `https://rook-ccc.github.io/Rookori/` を入力します。
2. **HTML タグ**を選び、表示されたタグの `content` の値だけを `site-config.json` の `googleSearchVerification` に入力します。空欄なら公開ビルドは確認タグを出力しません。
3. GitHub Pages に反映されたら、公開トップページのソース内に確認タグがあることを確認し、Search Console の **確認** を押します。
4. **サイトマップ**から `sitemap.xml` を送信し、**URL 検査**でトップページの状態を確認します。必要に応じてインデックス登録をリクエストします。 [所有権の確認](https://support.google.com/webmasters/answer/9008080?hl=ja) · [サイトマップ](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap?hl=ja)

`/Rookori/robots.txt` と `/Rookori/sitemap.xml` は公開ビルドに含まれます。検索エンジンがホストの巡回ルールとして読むのは `https://rook-ccc.github.io/robots.txt` です。プロジェクトサイトからホスト直下のファイルを管理する設定はないため、サイトマップは Search Console から直接送信します。 [Google の robots.txt の仕様](https://developers.google.com/search/docs/crawling-indexing/robots/robots_txt?hl=ja)

### Google Analytics 4（GA4）

1. Google Analytics の **管理**で GA4 プロパティを作り、**データ ストリーム → ウェブ**に公開URLを登録します。
2. ストリームの **拡張計測機能をオフ**にし、別の Google タグや Google Tag Manager のタグを追加せず、測定 ID をコピーします。拡張計測をオフにすると、ブラウザー履歴による二重計測や、フォーム・外部リンクなどの自動収集を避けられます。
3. 正式サイトは `site-config.cloudflare.json`、旧サイトは `site-config.json` の `ga4MeasurementId` を使います。公開先で「同意する」を選んだ後に限ってタグを読み込みます。
4. 公開後に **リアルタイム** を開き、Rookori で同意・画面移動して `page_view` を確認します。拒否時は送信しないことも確認します。集計後は **レポート → 集客 → 集客の概要** などで「アクティブ ユーザー」「新規ユーザー」を確認できます。数値は同意した利用環境での推計です。 [Analytics の設定](https://support.google.com/analytics/answer/9304153?hl=ja) · [手動ページビュー](https://developers.google.com/analytics/devguides/collection/ga4/views?hl=ja) · [ユーザー指標](https://support.google.com/analytics/answer/12253918?hl=ja)

手動ページビューには固定の画面名とURLを使います。Lichessユーザー名、棋譜、メモ、診断の回答・結果、学習履歴、元のURLのクエリや個別IDは渡しません。運営者は公開環境で、GA4管理画面の拡張計測（特に外部リンク、フォーム、履歴変更）とGoogleタグの自動イベント検出を確認し、開発者ツールのNetworkで同意前・同意後・撤回後の送信先と実際のパラメーターを確認してください。フッターの「アクセス解析とプライバシー」から同意の取り消しができます。 [Googleの拡張計測機能](https://support.google.com/analytics/answer/9216061?hl=ja)
